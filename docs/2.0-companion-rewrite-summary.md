# Playwright CLI Test Runner 2.0: Companion Rewrite Summary

Date: 2026-08-05  
Branch: `feature/playwright-cli-test-runner-2.0`  
Version: `2.0.0` (unreleased)  
Required extension: `ms-playwright.playwright`

## Executive summary

We modernized the former Playwright Test Runner extension and rebuilt version 2.0 as an editor-first companion to Microsoft's official Playwright extension.

The most important architectural decision was to stop owning native test execution. Microsoft is now the only Playwright `TestController` and owns Run/Debug results, status, output, duration, project/config selection, and debugging. This extension owns convenient CodeLens actions and scoped Playwright CLI tools.

The resulting ownership split is:

| Action | Implementation | Result owner |
| --- | --- | --- |
| File Run/Debug | VS Code URI-based Testing commands | Microsoft Playwright extension |
| Suite/test Run/Debug | Open document, move caret, invoke VS Code cursor Testing command | Microsoft Playwright extension |
| Inspector | `playwright test --debug` | Companion terminal and Playwright Inspector |
| Playwright UI | `playwright test --ui` | Companion terminal and Playwright UI |

This prevents duplicate native executions while keeping the project's strongest feature: CodeLens actions directly above files, suites, and tests.

## Starting point

The repository began from the released 1.4.1 implementation. It used the legacy `playwright.*` commands, parsed source files itself, constructed shell-oriented commands, and included report assets and an older Webpack/Mocha test structure.

The work started with a fix for nested selected-test matching:

- `67e4ed6 fix: select nested Playwright tests correctly`

The unreleased 2.0 rewrite then introduced modern discovery, testing, configuration, and build foundations. During review, we changed its direction from an independent VS Code test provider to an official-extension companion.

## Modernization work

### Build and project structure

- Replaced Webpack with an esbuild production bundle.
- Replaced the legacy ESLint configuration with flat ESLint configuration.
- Raised the runtime baseline to VS Code 1.93 and Node.js 20.
- Pinned the VS Code type definitions to 1.93 so newer APIs cannot accidentally enter the bundle.
- Added clean TypeScript test compilation to prevent deleted tests from remaining in `out`.
- Added VSIX packaging and tightened `.vscodeignore` so only runtime files ship.
- Removed obsolete screenshots, GIFs, report HTML/CSS, quick-start material, and the old `testarea` fixture.
- Preserved the existing package identity and unreleased `2.0.0` version.

### CLI discovery

The companion still needs Playwright CLI discovery to locate editor actions. It now:

- Finds standard Playwright configs across multi-root workspaces.
- Supports explicit config files and configless workspaces.
- Resolves local `@playwright/test`, `playwright`, or `playwright-core` installations.
- Falls back to the workspace package manager when no local CLI entry point is found.
- Runs `playwright test --list --reporter=json` and converts the result into a stable internal model.
- Supports nested suites, top-level tests, duplicate titles, dynamic tests, multiple configs, monorepos, and Playwright projects.
- Preserves structured executable and argument arrays until an interactive terminal command must be quoted.

## Official Playwright companion architecture

### Required dependency

`package.json` now declares:

```json
"extensionDependencies": [
  "ms-playwright.playwright"
]
```

The companion activates and validates the official extension before delegated Testing actions. It does not read Microsoft's private storage, test objects, or internal APIs.

### Editor selections

CLI discovery is flattened into serializable `EditorTestSelection` values containing:

- selection kind: file, suite, or test;
- target ID;
- URI and absolute file path;
- zero-based source position;
- optional full title;
- title-path components used for reliable CLI filtering.

These selections replace the former dependency on this extension's own `TestItem` tree.

### CodeLens layout

The editor layout remains:

```text
Run File · Debug File · Playwright UI

Run Suite · Debug Suite · Inspect Suite · Playwright UI
test.describe('checkout', () => {

  Run Test · Debug Test · Inspect Test · Playwright UI
  test('submits an order', async ({ page }) => {
```

### Official bridge

`OfficialPlaywrightBridge` maps selections to built-in VS Code Testing commands:

- File Run: `testing.run.uri`
- File Debug: `testing.debug.uri`
- Suite/test Run: `testing.runAtCursor`
- Suite/test Debug: `testing.debugAtCursor`
- Refresh: `testing.refreshTests`
- Rerun: `testing.reRunLastRun`

For positioned selections, the bridge opens the correct document, moves and reveals the caret, and leaves it at the selected test. This lets Microsoft's asynchronous discovery resolve the intended test reliably.

The bridge reports clear errors when the official extension or required Testing commands are unavailable.

### Companion CLI operations

Inspector and Playwright UI remain separate CLI operations because the official extension exposes no callable API for them:

- Inspector uses `playwright test --debug`.
- Playwright UI uses `playwright test --ui`.
- File paths are resolved relative to the configured working directory when possible.
- Config, environment, extra CLI options, paths containing spaces, and selected CLI projects are preserved.
- CLI project selection is persisted separately from Microsoft's enabled projects.
- Inspector/UI intentionally do not create or update native VS Code test runs.

The report, trace, and codegen terminal commands were retained.

## Removed duplicate workflows

The following 2.0 work was removed after adopting the companion architecture:

- independent `TestController` and run profiles;
- duplicate Playwright runner and TestRun manager;
- bundled live NDJSON reporter;
- JSON report import into the Testing view;
- snapshot TestController workflow;
- `additionalReporters` configuration;
- Testing-item context menu contributions.

Snapshot behavior is now owned by Microsoft. Removed legacy features display migration notices where appropriate.

The extension export is now:

```ts
{
  discovery,
  projects,
  bridge
}
```

## Commands and migration

The supported command set includes:

- Refresh Tests
- Configure CLI Projects
- Open Microsoft Playwright Settings
- Run/Debug test or file
- Inspector
- Playwright UI
- Rerun Last Run
- Show HTML Report
- Show Trace
- Record New Test with codegen
- Migrate Legacy Settings

Legacy `playwright.*` aliases are retained when they do not conflict with the upstream extension. Run/Debug aliases delegate to the new behavior. Obsolete string regex arguments are normalized before forwarding so older command integrations cannot cause property or `in`-operator errors.

The extension reads legacy `playwrightrunner.*` settings only when a corresponding new setting is absent. Explicit empty new values correctly restore automatic behavior instead of falling back to legacy values.

## Real-world issues found and fixed

### Electron consumed `--debug`

The first Inspector test launched a command beginning with VS Code's macOS helper:

```text
Code Helper (Plugin) .../@playwright/test/cli.js test --debug ...
```

Inside the extension host, `process.execPath` is Electron rather than a standalone Node executable. Electron consumed `--debug` and printed the deprecated `node --debug` error.

The fix applies `ELECTRON_RUN_AS_NODE=1` whenever a locally installed Playwright CLI is run through the extension-host executable. The same environment is used by background discovery and interactive terminals, fixing Inspector, UI, report, trace, and codegen launches.

The exact macOS helper invocation was verified to run Playwright and report version 1.62.1.

### Selected test returned “No tests found”

The repository case was documented in:

```text
abbiz_bizone-design-system-ib-playwright/docs/
vscode-playwright-test-runner-selected-test-issue.md
```

The affected test was:

```text
Verify Dropdown Logic › TC_028 Verify dropdown menu viewport placement
```

Two selection problems were addressed:

1. The generated file argument now preserves `tests/dropdown.spec.ts` instead of using only `dropdown.spec.ts`.
2. Grep filters no longer assume that a discovered space-joined title begins at the start of Playwright's searchable title.

Playwright's searchable title may contain a project/file prefix, non-whitespace title separators, and trailing tags. The new filter:

- keeps individual suite/test title components;
- escapes each component;
- permits separator text between components;
- permits Playwright's project/file prefix;
- permits trailing tags after a selected test.

The generated filter was verified directly against the real repository and selected exactly one Chromium `TC_028` test.

### Data-driven tests repeated CodeLens actions

Playwright expands loop-generated and data-driven tests during discovery. Every generated case can therefore have a different title while pointing to the same `test(...)` source declaration. Flattening each discovered case separately produced another complete Run, Debug, Inspect, and UI group on the same editor line.

Selections are now collapsed by kind, normalized file, line, and column. The selection retains the generated title paths for diagnostics, but only one CodeLens action group is rendered at a shared declaration.

The execution behavior is split deliberately:

- Run and Debug still delegate the shared cursor location to Microsoft's extension.
- Inspector and Playwright UI use Playwright's `file:line` filter when multiple generated tests share the declaration, selecting every generated case at that exact source line without building a large grep alternation.
- Positional file filters are emitted before variadic options such as `--project`, preventing Playwright from consuming `file:line` as another project name.

The fix was verified against the reported `checkbox_label.spec.ts:17` case. One source declaration selected all 26 generated Chromium tests while rendering a single CodeLens group.

### Review hardening fixes

The following review findings were also resolved:

| Priority | Finding | Resolution |
| --- | --- | --- |
| P1 | Project/file prefixes and tags broke grep filters | Added component-aware, prefix/separator/tag-tolerant filters |
| P2 | Execution-setting changes left resolved targets stale | Added configuration invalidation and serialized full refreshes |
| P2 | Root configs intercepted nested config/test refreshes | Added exact-config and deepest-directory refresh routing |
| P2 | New/deleted configs did not rescan targets | Added config file watching and target rescans |

| P2 | Persisted CLI projects became stale after rename/removal | Reconciled stored projects with the latest discovery model |

| P3 | Legacy string arguments crashed new handlers | Normalized legacy cursor-command arguments and hardened type guards |

## Intentional boundaries

- Microsoft remains the sole native Playwright test provider.
- Inspector and Playwright UI remain independent CLI sessions and do not update Microsoft Testing results.
- Official project/config selection stays private to Microsoft.
- Companion CLI project selection is separate and explicitly configured with **Configure CLI Projects**.
- Generic VS Code cursor Testing commands may also select another unrelated provider if it claims the exact same source range.
